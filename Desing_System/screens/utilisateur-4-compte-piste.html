Administrer le compte d'une personne — quatre actes nommés dans un menu, dessinés nulle part

Ce que la fiche utilisateur avait laissé ouvert. Son menu de débordement nomme suspendre, supprimer, réinitialiser le code PIN et réinitialiser le mot de passe : quatre entrées qui ouvraient le vide. Cette planche les dessine, dans le même moule que les feuilles d'attribution — une feuille montante, la conséquence avant le bouton.

Ce n'est pas « Mon compte ». Les quatre actes de cette planche sont ceux d'un administrateur sur le compte de quelqu'un d'autre : il ne connaît pas le mot de passe, il envoie un lien. Agir sur son propre compte — mot de passe, double authentification, sessions, code PIN — est un autre acte, avec une seule vue de référence : « Mon compte », planche 07.1. Le titre de cette planche a été renommé le 31/07 pour que les deux ne se confondent plus, et aucune des deux ne recopie l'autre.

Cadrage. À qui : le super-administrateur, et lui seul. Quelle décision : couper un accès, effacer une personne, ou remettre une preuve à zéro. Ces quatre actes n'ont rien en commun sauf leur emplacement — c'est pourquoi ils ne partagent aucune formulation générique du type « Êtes-vous sûr ? ».

Une règle de couleur, et elle vient du brief

Le menu actuel marque Suspendre en rouge. C'est une erreur : suspendre est réversible — « Réactiver le compte » existe déjà comme geste primaire sur la fiche d'un compte suspendu. Le rouge est réservé à l'irréversible (§8.8), c'est-à-dire à la suppression seule. Les trois autres feuilles gardent donc le geste primaire dans la couleur d'action de l'écran ; la quatrième est rouge, et elle est la seule.

Supprimer un compte n'efface pas la chaîne de preuve

C'est le point neuf de la planche, et il touche la doctrine entière. Une suppression suit la même grammaire en trois temps que « Sortir du parc » — ce qui disparaît, ce qui reste, ce que ça coûte — et le deuxième temps porte l'essentiel :

Les attestations que la personne a signées — remises, réceptions, restitutions, avec son nom et l'horodatage — ne s'effacent pas. Si elles partaient avec le compte, toute la double attestation tomberait le jour d'un départ, et deux ans d'historique deviendraient des lignes anonymes.

Le compte disparaît, la trace des passages de main reste. Corollaire d'interface : le motif est obligatoire — c'est la dernière chose qu'on saura de cette personne dans le parc.

Réinitialiser le code PIN a une conséquence sur les remises

C'est la seule raison de dessiner cette feuille. Tant que la personne n'a pas redéfini son code, ses prochaines réceptions passent par signature — exactement la règle de la 4ᵉ colonne de la planche 05.3 (compte en attente, pas de code, donc signature), appliquée cette fois à un compte existant. Le dire dans la feuille évite de le découvrir au comptoir, l'objet dans les mains.

Le menu n'est pas la même liste pour tout le monde — il se lit dans la donnée

Contradiction relevée dans ma propre planche : la fiche d'Alice annonce « Connexion : Annuaire d'entreprise » et offre « Réinitialiser le mot de passe ». L'application ne peut pas réinitialiser un mot de passe qu'elle ne détient pas.

Correction : l'entrée n'apparaît que sur un compte à mot de passe local. Sur un compte annuaire elle est absente, et c'est la rangée de référence « Connexion » qui porte la destination — mot de passe géré dans l'annuaire. Même traitement en miroir pour le code PIN : rien à réinitialiser tant qu'aucun code n'est défini. Une action impossible se masque, elle ne se grise pas — la règle est déjà celle de la suppression d'un compte qui détient du matériel.

Cela ferme la question ouverte n°5 du §9 côté interface : la réponse n'est pas « annuaire » ou « local », c'est les deux, et l'écran le lit dans la donnée. Le réglage « mode de connexion » du panneau bascule les cinq colonnes d'un compte à l'autre.
