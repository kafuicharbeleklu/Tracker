La première connexion — accepter l'invitation, ouvrir son compte

Le seul trou d'un parcours déjà dessiné. L'informatique crée une personne (planche 05.3), lui attribue des équipements (06.1), et la personne les confirme avec son code PIN (06.2). Entre les deux, rien n'était dessiné : ni comment on entre la première fois, ni où le code PIN se définit quand il n'a jamais existé. La planche 06.2 dessinait bien le formulaire de code — mais seulement après une réinitialisation, c'est-à-dire pour quelqu'un qui a déjà un compte.

Ce que cette planche ne redessine pas. Le bandeau de marque vient de la planche 02.1, le champ de code PIN de la planche 06.2, la fiche personne de 05.2. Une arrivée ne mérite pas de composants à elle : elle mérite l'ordre dans lequel on les rencontre.

Une arrivée demande deux secrets, et l'écran dit lequel sert à quoi avant de les demander.Le mot de passe ouvre l'application. Le code PIN vaut signature. Ce sont deux objets différents, et c'est la seule confusion qui compte ici : une personne qui croit avoir « un code » en aura deux, et retapera le mauvais devant l'informatique le jour d'une remise. Ils se demandent donc l'un après l'autre, sur deux écrans, chacun avec sa phrase — jamais dans un même formulaire d'inscription.

Relevé — ce qui arrive avant l'écran

Le courriel n'est pas de la maquette : il est le premier écran du produit, et le seul que l'informatique ne voit jamais. Il dit qui invite — une invitation anonyme se lit comme du hameçonnage — et ce qui attend, parce que c'est la seule raison de cliquer. Il ne porte aucun mot de passe provisoire : un mot de passe envoyé par courriel est connu de tous ceux qui liront ce courriel, et il survivra dans la boîte pendant des années.

Un tunnel d'arrivée se juge sur ses ratés, parce qu'ils arrivent à la personne qui ne connaît pas encore le produit et qui n'a personne à qui demander. Les quatre cas ci-dessous se règlent tous sans support, sauf le dernier — et celui-là le dit franchement plutôt que de faire semblant.
