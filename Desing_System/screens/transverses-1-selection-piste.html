Vues transverses — la sélection et la confirmation

Deux vues dessinées une fois, employées vingt fois. La barre d'actions groupées sert quatre écrans — Tâches, Catalogue, Inventaire, Utilisateurs. La confirmation destructive en sert neuf : le code la consomme par contexte (useConfirmation), pas comme un composant local. Les dessiner avant les écrans qui les portent, c'est ne pas les dessiner vingt fois.

La sélection multiple n'est pas une hypothèse : elle est déjà dans le code. ManagementPage porte « Exporter la sélection » et « Supprimer la sélection ». La question restée ouverte depuis le 28/07 — la file permet-elle la sélection multiple ? — est donc close, et le patron n'attend plus qu'un dessin.

État — entrer en sélection

La sélection ne s'invente pas : elle a deux entrées. L'appui long sur une rangée, que les habitués trouvent seuls, et une entrée écrite dans le débordement, pour tous les autres — un geste caché n'est pas un geste, et l'appui long ne s'annonce nulle part.
Le point de bascule est la rangée elle-même : la vignette cède la place à une case, au pixel près — même position, mêmes 40 px. Le texte ne bouge pas d'un point. La cible tactile, elle, déborde à 48 px sans que rien ne se voie.

État — sélection à un, puis à cinq

La barre du haut est remplacée, pas recouverte. Elle passe en sombre et son geste de sortie prend la place du retour. L'écran change de régime ; il ne gagne pas une couche.
Le compte devient le porte-voix — Archivo 28, l'unique palier haut de l'écran, avec l'ancre qui le qualifie sous lui. En régime de sélection, le sujet n'est plus la file : c'est ce qui est coché. R1 tient, le porte-voix a seulement changé de porteur.
Le pied ne contient que les actes possibles sur la sélection courante, et il n'existe pas à sélection vide. C'est la règle : jamais d'acte grisé en attente d'une sélection.

État — la confirmation, trois natures

Une feuille, jamais une boîte centrée. Elle monte du bas, donc elle arrive sous le pouce ; ses deux gestes sont à portée sans changer de main.
La question porte le nom du sujet — jamais « cet élément », jamais « voulez-vous vraiment ». Et le corps dit la conséquence, pas l'action répétée : ce que l'utilisateur veut savoir, c'est ce qui aura changé après.
Le bouton porte le verbe. Jamais « OK », qui oblige à relire la question pour savoir ce qu'on approuve.

Relevé — les règles, et les vingt emplois

Deux vues, vingt emplois. Chaque règle ci-dessous répond à un défaut relevé dans les planches ou dans le code — aucune n'est une préférence.

S1

Aucun acte grisé en attente d'une sélection

Le pied d'actions n'existe pas à sélection vide ; il apparaît au premier élément coché. Un bouton grisé demande à l'utilisateur de deviner ce qui le débloquerait.

S2

Deux entrées, dont une écrite

L'appui long et une entrée « Sélectionner » dans le débordement. Un geste qui ne s'annonce nulle part n'est découvert que par ceux qui le connaissaient déjà.

S3

Le compte se qualifie

« 5 sélectionnés sur 17 », jamais « 5 ». Le dénominateur est ce qui permet de juger si la sélection est complète — c'est la même règle que le repère de rythme sur un chiffre de tête.

S4

Jamais un acte au seul survol

Tout est tactile : un geste qui n'apparaît qu'au survol n'existe pas ici. Les actes de rangée sont visibles en permanence ou dans le débordement.

C1

Le sujet est nommé

« Supprimer Latitude 5540 », jamais « supprimer cet élément ». Sur une sélection, c'est le compte qui nomme : « Refuser les 5 demandes ».

C2

Le corps dit la conséquence

Ce qui aura changé après — pas l'action répétée en plus long. Ce qui est conservé se dit aussi : l'historique, les équipements détenus, les mouvements.

C3

Le bouton porte le verbe

« Supprimer », « Suspendre », « Refuser ». Jamais « OK » ni « Confirmer », qui obligent à relire la question. Le rouge #B3261E est réservé à l'irréversible ; le réversible est sombre.

C4

L'irréversible le dit

Une ligne, en rouge, sous le corps. C'est la seule différence entre supprimer et suspendre du point de vue de l'utilisateur, donc elle doit être la plus visible.
