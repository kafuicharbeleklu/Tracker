La preuve — ce qui choisit la méthode, et comment elle se saisit

La question posée. « Comment est déterminé le choix de la méthode ? Seul le code PIN semble disponible. » Les trois méthodes — signature, code PIN, empreinte — existent depuis la planche 7. Mais elles y sont pilotées par un réglage de planche : un interrupteur de maquettiste, pas une règle d'écran. Le défaut n'est pas qu'il manque des méthodes : c'est que rien ne montre ce qui décide. Cette planche le dessine.

La forme de la preuve dépend d'un fait, jamais d'une préférence.Personne ne « choisit » sa méthode dans un menu déroulant : l'écran lit trois faits — les deux parties sont-elles ensemble, la personne a-t-elle un code, l'appareil sait-il lire une empreinte — et propose une méthode, avec une seule sortie de secours. Un choix libre ferait de la preuve une préférence, et une preuve choisie ne prouve rien.

Vue — ce qui décide, trois faits dans cet ordre

L'ordre compte : on descend l'arbre et on s'arrête au premier oui. Aucun écran ne demande « quelle méthode voulez-vous ? » — la méthode est proposée, et l'unique bouton secondaire permet d'en changer une fois, avec sa raison. Le dernier cas est le plus fréquent et le plus mal traité aujourd'hui : quand personne n'est en face, on n'invente pas une preuve.

Et la sortie de secours

Chaque feuille porte un bouton secondaire — « Signer à la place » ou « Utiliser mon code » — qui bascule vers la méthode voisine, une fois, et l'inscrit dans l'attestation.
La méthode employée est toujours écrite dans l'historique : « signature », « code PIN », « empreinte ». C'est ce qui rend le passage de main relisible deux ans après.

Réponse au point 1

Les trois méthodes sont définitives — ce sont celles du produit. Ce qui manquait, c'est la règle, et elle est ici.

Une quatrième est envisageable et non tranchée : le QR code présenté par la personne. À décider avec l'équipe, pas en maquette.

État — le champ code PIN, ses cinq temps

Un seul composant, identique sur tous les écrans. Le chiffre qui vient d'être tapé reste lisible le temps de le relire ; les précédents sont masqués. C'est ce qui permet de corriger une frappe sans jamais exposer le code entier — la faute la plus commune des champs à code, et la plus coûteuse ici, puisque ce code vaut signature.

État — définir un nouveau code, le formulaire qui manquait

Le pendant de « Réinitialiser le code PIN » (planche 05.4), côté personne. Il se présente à la première connexion suivant la réinitialisation, et il dit d'abord pourquoi il est là. Deux saisies, jamais une : un code qu'on ne peut plus relire ne se retrouve pas. Et il refuse les suites évidentes — c'est le seul moment où l'application a le droit d'être exigeante, puisque ce code vaudra signature.

État — les deux autres méthodes, et le cas sans preuve

Même structure, même place dans la feuille : seul le bloc de preuve change. La signature est la plus forte — manuscrite, datée, et personne ne signe par distraction. L'empreinte ne se pose que sur son propre appareil. Et quand personne n'est en face, la quatrième case est vide : l'objet reste en attente et la preuve viendra plus tard, ou pas.

Une seule vue de référence

Ces trois blocs sont le même composant de preuve : ils s'insèrent à la même place, dans la même feuille, quel que soit l'acte — remise, réception, restitution, réception de retour.
